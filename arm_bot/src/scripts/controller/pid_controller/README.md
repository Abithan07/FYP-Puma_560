# PID Controller - Enhanced with Trajectory Tracking

## Quick Summary

You now have **two PID controllers**:

| Feature | `pid_controller.py` | `pid_controller_trajectory.py` |
|---------|-------------------|--------------------------------|
| **Purpose** | Point-to-point control | Trajectory tracking |
| **Input** | Single target configuration | Generated or loaded trajectory |
| **Motion** | Direct drive to target | Smooth minimum-jerk path |
| **Use Case** | Go from A to B | Track pre-planned smooth trajectory |
| **Output Format** | `pid_log_*.csv` | `pid_traj_log_*.csv` |

## Controller Comparison

### Original Controller: `pid_controller.py`
**Point-to-Point Movement - Direct path to target**

```bash
python3 pid_controller.py --target 45 60 90
```

- Moves directly from current position to target
- Immediate error computation: `error = target - current`
- Simple but can cause jerky motion
- Good for: Quick positioning, emergency stops

---

### New Controller: `pid_controller_trajectory.py`
**Trajectory Tracking - Follow smooth path**

#### Mode 1: Generate Trajectory
```bash
python3 pid_controller_trajectory.py \
    --target 45 60 90 \
    --T 20
```

- Generates smooth minimum-jerk trajectory
- Tracks reference position, velocity, and acceleration
- Feedforward control for better tracking
- Auto-computes duration if `--T` not specified

#### Mode 2: Load Trajectory from CSV
```bash
python3 pid_controller_trajectory.py \
    --trajectory-csv /path/to/trajectory.csv
```

- Loads pre-computed trajectory from dataset
- Supports row-wise CSV format (same as `plot.py`)
- Can integrate with trajectory generation pipeline

---

## Trajectory Tracking Control Law

$$\tau = K_p e_p + K_d e_v + K_i \int e_p \, dt + K_{ff} \ddot{q}_{ref}$$

Where:
- **$e_p = q_{ref} - q$**: Position error
- **$e_v = \dot{q}_{ref} - \dot{q}$**: Velocity error  
- **$K_{ff}$**: Feedforward gain on reference acceleration (0.1 × $\ddot{q}_{ref}$)

**Key difference from point-to-point:**
- Reference values come from **trajectory** instead of single target
- Derivative error uses **reference velocity** for better damping
- Feedforward term helps track acceleration changes

## CSV Trajectory Format

The trajectory CSV (used with `--trajectory-csv`) must be **row-wise** format:

```
t,        0.0,      0.01,     0.02,    ... (time values)
dp1,      0.0,      0.001,    0.005,   ... (joint 1 position, rad)
dp2,      0.785,    0.786,    0.787,   ... (joint 2 position, rad)
dp3,      2.356,    2.358,    2.361,   ... (joint 3 position, rad)
dv1,      0.0,      0.1,      0.2,     ... (joint 1 velocity, rad/s)
dv2,      0.0,      0.15,     0.3,     ... (joint 2 velocity, rad/s)
dv3,      0.0,      0.12,     0.24,    ... (joint 3 velocity, rad/s)
da1,      0.0,      10.0,     10.0,    ... (joint 1 accel, rad/s²) [optional]
da2,      0.0,      15.0,     15.0,    ... (joint 2 accel, rad/s²) [optional]
da3,      0.0,      12.0,     12.0,    ... (joint 3 accel, rad/s²) [optional]
```

**Note:** This is the same format generated by `trajectory_generator.py` and used by `plot.py`

## PID Gain Tuning

### Default Gains (PUMA-560 optimized)
```
Kp = [50,   200,  150]   (proportional)
Ki = [5,    25,   20]    (integral)
Kd = [12,   35,   10]    (derivative)
```

### Tuning Guidelines

| Goal | Action |
|------|--------|
| **Faster response** | ↑ Kp, ↑ Kd |
| **Reduce error** | ↑ Ki, enable feedforward |
| **Less oscillation** | ↑ Kd, decrease vel_filter_alpha |
| **Aggressive** | Increase all gains by 1.5-2x |
| **Gentle** | Decrease all gains by 0.5-0.75x |

```bash
# Example: Aggressive tuning
--kp 75 300 225 --ki 7.5 37.5 30 --kd 18 52.5 15
```

## Key Parameters

### For Trajectory Generation (`--target`)
- `--T DURATION`: Total trajectory time (seconds)
  - Auto-computed if omitted (constraint-based: 2 rad/s max velocity, 7 rad/s² max accel)
- `--start Q1 Q2 Q3`: Start configuration in degrees (default: 0 45 135)

### For Control
- `--kp, --ki, --kd`: PID gains for each joint [j1 j2 j3]
- `--torque-limits`: Maximum torque per joint (default: 2.0 45.0 10.0 Nm)
- `--dt`: Control period (default: 0.01s for 100 Hz)
- `--vel-filter-alpha`: Velocity filter smoothing 0-1 (default: 0.25, higher = more filtering)
- `--settle-tolerance-deg`: Error tolerance to declare "settled" (default: 1.0°)

### For Feedforward
- `--no-feedforward`: Disable acceleration feedforward (enabled by default)

## Trajectory Generation Constraints

When auto-computing duration with `--target`:

**Minimum velocity time:** $T_{vel} = \frac{1.875 \cdot \Delta q}{v_{max}}$ where $v_{max} = 2.0$ rad/s

**Minimum acceleration time:** $T_{acc} = \sqrt{\frac{5.77 \cdot \Delta q}{a_{max}}}$ where $a_{max} = 7.0$ rad/s²

**Required duration:** $T = \max(T_{vel}, T_{acc})$

**Example:** 1 radian movement requires minimum 0.9375 seconds

## Troubleshooting

### High Tracking Error
**Solution:** 
1. Increase `--kp` (proportional gain)
2. Increase trajectory duration `--T`
3. Check robot velocity/torque saturation

### Oscillations/Ringing
**Solution:**
1. Increase `--kd` (derivative damping)
2. Decrease `--vel-filter-alpha` (more filtering)
3. Lower `--kp`

### Slow Response
**Solution:**
1. Increase `--kp` and `--kd`
2. Decrease `--T` (shorter trajectory)

### Trajectory Won't Load
**Solution:**
1. Verify CSV has headers: `t, dp1, dp2, dp3, dv1, dv2, dv3`
2. Check file path
3. Use `plot.py` to verify CSV format
